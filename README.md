# 微信听写可行性测试器

这个小工具仅验证两件事：

1. 微信是否接受程序通过 `SendInput` 模拟的 `Ctrl+Win` 按住/松开事件。
2. 微信是否能将最终识别文字写入普通 WinForms `TextBox`，从而由程序读取。

## 测试方法

1. 确认电脑版微信已运行，并且手工使用 `Ctrl+Win` 可以正常听写。
2. 启动测试器。
3. 测试 A：在绿色按钮上按住鼠标，说一句话，然后松开。
4. 如果微信没有被唤起，执行测试 B：点击“仅聚焦接收框”，随后手工按住 `Ctrl+Win` 说话并松开。

## 结果解释

- 测试 A 成功：模拟触发和结果捕获均可行。
- 测试 A 失败、测试 B 成功：微信拒绝模拟快捷键，但结果捕获可行；可改用微信原生快捷键、虚拟 HID 或其他触发方式。
- 测试 A、B 都失败：微信没有向普通文本控件写入，需要进一步分析其目标控件识别方式。

## 远控回填测试

1. 保持测试器运行。
2. 切换到任意远程控制客户端，在远端文本框中点出光标。
3. 查看测试器底部显示的“当前桥接热键”。程序会从 `Ctrl+Alt+F9` 等多组候选键中自动选择未被占用的一组。
4. 在远端输入框中按一次当前桥接热键；测试器会记录远控窗口、切换到本地接收框并开始微信听写。
5. 说完后再按一次同一组热键。
6. 测试器等待识别结果稳定后，将文字放入剪贴板、恢复原远控窗口并发送 `Ctrl+V`。

本测试会覆盖当前文本剪贴板，并暂时保留识别结果，便于粘贴失败时手工重试。

### Ulanzi 插件前置验证：焦点跳板模式

屏幕右上角的绿色悬浮按钮模拟 Ulanzi 插件按下/松开事件：

1. 在远控客户端内点出远端输入光标。
2. 按住绿色悬浮按钮说话。
3. 松开按钮结束。
4. 程序临时激活本地接收框并调用微信；识别完成后复制结果，保持主窗口显示，同时把焦点交还之前的远控窗口并发送 `Ctrl+V`。
5. 如果自动粘贴失败，识别文字仍保留在主窗口；可点“复制结果”后手动切换到目标窗口粘贴。

如果文字能够进入远程输入框，就可以将悬浮按钮回调替换为 Ulanzi SDK 的 `onKeyDown/onKeyUp`。

本工具不注入微信进程、不读取微信内存、不调用私有接口，也不会联网。
